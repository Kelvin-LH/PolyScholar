# 多智能体研发计划与交付门槛

日期：2026-10-02。目标为个人本地跨平台桌面研读工具；范围不扩展为 B/S、浏览器产品、团队服务或账户同步。界面依据 [UI 规范](10-ui-spec.md)。原有 P0 需求仍是目标范围，不代表已经交付。

文献管理新增 Zotero 对标要求，采用 [对标矩阵](12-zotero-parity.md) 的 Z-LIB-01–08 逐项验收，不能把基础列表、标签字符串和 PDF 导入称为完整对齐。

技术决策更新：全部自有应用代码用 Python；PySide6 原生桌面与 sqlite3/Python 服务，旧栈验证不作为新架构完成证据。三平台冻结包与安装仍须分别验收。

## 本轮团队与目标

| 工作角色 | 负责范围 | 首轮交付标准 |
|---|---|---|
| 产品/UI 与独立 QA | 六类屏幕状态、信息架构、需求追踪、异常路径审查 | 设计规范、开发门槛、基线检查与问题报告 |
| 界面工程 | Python/PySide6 原生控件、导航、真实数据绑定、空态与交互 | 六个可访问页面，未实现按钮明确禁用，界面构建通过 |
| Python/桌面工程 | PySide6 主窗口、本地文献数据、Python 服务与工作进程、平台依赖 | 最小权限、后端校验、本地持久化与真实构建证据 |
| 协调与集成 | 统一接口、分支/变更集、检查、GitHub 推送与自动推进 | 可复现开发命令、准确状态文档、通过检查的变更 |

智能体共享仓库，按文件边界协作；发现跨边界问题先通知负责人。只有协调者执行最终提交/推送，防止互相覆盖。运行时私人文献、API 密钥、用户库和引擎缓存不进入提交。

## 分阶段目标

1. **D1 可审查 UI 与桌面骨架**：六屏设计、真实空库、路由/导航、已有文献选择、明确能力状态，初始化桌面入口与构建流程。设计示例不写入用户库。
2. **D2 本地文献闭环**：PDF 文件选择、校验、哈希去重、复制与持久化，读写冲突/磁盘错误、重启保持，原件不变。库内检索仅本地执行。分 D2a 集合/子集合与多集合成员、标签/筛选；D2b 类型化元数据、父条目/多附件、重复候选与人工合并；D2c 高级/全文搜索、回收站、规范引文导入导出，不一次虚称 Zotero 全量一致。
3. **D3 阅读与翻译闭环**：真实 PDF 渲染/选段定位、固定版本引擎探测、OS 凭据库、授权、任务启动/取消、输出验证和本地任务记录。尚未接入能力不得启用。先合成/公开合法测试，不用用户私人论文或付费 API。
4. **D4 证据与引用闭环**：结构化摘要来源校验、实际引用处理器/合法样式、错误/降级、真实文件导出；用金标检查，不由 LLM 猜补。
5. **D5 跨平台发行**：Windows/macOS/Linux 分别构建、安装与完整路径验证，实际引擎资源联网载荷检查、秘钥和临时文件、SBOM 与许可。只发布经过验证的平台包。

D1/D2 是本轮开发方向，D3–D5 需持续推进，不能因 UI 原型完成就宣称 MVP 已完成。详细任务沿用 [实施路线](06-roadmap.md) 的 A01–A08 与 [产品需求](02-requirements.md) 中的需求 ID。

本轮新增可独立交付的桌面易用性工作：E01 自动发现/探测所选引擎解释器，自定义路径放折叠高级区；E02 可选择任务缓存目录，验证可写并明确上游资源缓存覆盖范围；E03 已生成译文 PDF 的原生保存导出，实际写入才成功，拒绝覆盖原件。它们不取代 Zotero 对标工作，也不能因设计写入文档就标为已实现。

## 必须报告的验证层次

| 层次 | 能证明 | 不能证明 |
|---|---|---|
| Python 基线与合成引擎测试 | SQL/文档/适配器部分契约、可恢复的合成执行与清理 | 真实翻译质量、付费 API、上游实际联网载荷 |
| Python 领域与服务测试 | Python 服务与协议的已测边界行为 | 桌面窗口已运行、跨平台安装成功 |
| PySide6 控件/信号与打包检查 | 原生界面可加载、信号交互及当前平台冻结产物 | 三平台安装成功、真实翻译质量 |
| 本机桌面构建与运行 | 当前 OS/架构的真实桌面启动与操作 | 其他平台或发行签名 |
| 三平台安装/端到端 | 已记录版本和环境的测试路径 | 任意 PDF 都无损、任意模型都可信 |

应用自有代码统一 Python，界面使用 PySide6 Widgets；不使用 WebView/React，不启动开发或生产 HTTP 应用服务。PyInstaller/pyside6-deploy 冻结发行自带 Python，用户无需先安装解释器；两个引擎独立环境仍需随包验证。不增加服务端账户或云数据库。

## QA 检查清单

- LIB-01：真实空态、首次导入、损坏/伪 PDF、空文件、重复附件、特殊字符路径、重启保存；原件哈希保持不变。
- PRIV-01：模型 API 与资源下载按用户本轮授权默认允许，任务页不要求两个手动勾选；仍核对实际处理范围及目的地，图片外发等未授权扩展另行确认，密钥不进 argv/日志/普通持久化；Linux 无安全凭据库的明确失败路径。
- TRANS-02：进程错误、超时、取消、重复启动与输出路径冲突，部分结果不能标为完整成功；暂不支持的恢复/预算功能保持禁用。
- READ-01/SUM-01：真实页码/块锚点、解析修订变化、失效定位、缺证据状态，无假页面和假摘要。
- CITE-01：缺失元数据与格式差异、保存取消/错误、合法样式版本，成功必须对应实际文件。
- TRACE-01：本地记录与导出来源可核查，用户内容不自动标 AGPL，代码来源记录不作为法律授权证明，不做隐藏遥测。
- 界面：六屏键盘访问、长标题/路径、缩放、窄窗口、焦点和可访问名称；按钮能力状态与后端一致。
- Z-LIB：集合层级/循环拒绝、多集合成员不复制、移除与删除语义、标签联合搜索、不同条目类型字段、附件角色、重复候选人工决策和回收恢复，逐项核对对标矩阵。
- E01–E03：解释器缺失/错版本、自定义覆盖与发现优先级；缓存目录无权限/活动任务/旧缓存；导出取消、覆盖原件、磁盘写入失败、文件哈希保持。
- 发布：实际三平台 Qt 插件/密钥库/进程树与临时文件权限；无法执行的项目记录为未验证，不以 CI 图标代替。

## 定时推进与推送纪律

协调者通过 Codex 的当前聊天 heartbeat 配置周期研发；周期与自动化实际创建结果以聊天记录为准，本文不伪造已排定或已执行的定时任务。每轮先查看工作树、最新进度与检查结果，选择尚未完成的可验证任务，必要时重新组建多智能体团队。

只有形成实质变更且相关检查通过才提交并推送；没有变更不制造空提交。检查失败先修复，环境限制须记录。按用户选定的每小时周期报告实际进度；无变化时明确说明没有新增进展。不将私人文件、运行数据库、缓存、密钥或未授权数据推送 GitHub；不自动合并他人 PR 或发布未验证安装包。

定时研发是后续增量推进，不保证机器离线时执行，也不保证每个时间点产生可推送成果。每次交付列出改动、验证证据、限制和下一目标。

## 初期已交付的基础能力

Python/PySide6 六屏基础实现、本地库服务、PDF 阅读、会话模型设置、模型列表获取、缓存路径与译文导出均已有代码；33 项 Python 测试通过。本机 macOS arm64 开发 `.app` 已启动检查，未公开发布。该阶段集合树尚未完成；后续集合树交付见下文 D2a。多附件、高级检索与回收站继续推进。

## D2a 本轮进展

集合/子集合增改删、成员多对多、全部/未分类视图、可选子集合筛选、标签联合过滤及全局标签管理已接入原生界面。38 项本地 Python 测试与原生交互检查通过，已有库升级前保存 v1 备份。多附件、类型化元数据、高级/全文检索、书目合并与回收站仍待实现。

## 审查整改

依据 [整改追踪](14-review-remediation.md) 持续自查；未关闭的真实引擎/联网/安装与 DocumentIR 项继续作为交付门槛。

## DocumentIR 基础

SQLite v4 与实际本地 PDF 文本解析已接入；支持带页码/坐标的人工证据笔记、原文逐字校验、重解析失效标记。继续推进结构化模型摘要、OCR、复杂版面阅读顺序与 Zotero 多附件等目标。V1–V5 和安装门槛保持开放。


## 选段模型摘要进展

已接入显式选段、API 发送范围预览、结构化类别与归属、模型来源持久化和多引用定位。SQLite v5 原子保存及受监督网络 worker 的总超时回归通过。继续推进真实模型金标评测、费用预算、OCR/章节聚合、Zotero 多附件及发行门槛；不将合成响应视为真实模型验收。


## D2b 托管多 PDF 附件

SQLite v6 与原生附件列表已接入，根条目维持书目/集合关系，子 PDF 独立承载阅读、IR、摘要及任务。88 项本机测试和附件原生冒烟通过，独立复审修复隐藏附件重复导入和刷新丢失选择。继续推进类型化元数据、链接附件、书目去重合并、高级检索与回收站；Z-LIB-04 尚未全量完成。


## D2b 类型化文献与作者

四类文献、类型字段、有序个人/机构作者和编者已接入原生编辑与 CSL JSON/BibTeX/RIS 导出。旧姓名保持完整文本；类型切换保留隐藏字段并提示。独立复核先复现 Unicode 换行破坏 RIS 记录和全角日期被接受，再修复并加入回归。继续推进无文件条目、书目合并、高级检索、回收站及既定发行门槛。


## D2c 高级元数据检索与保存搜索

团队按后端、原生界面和独立回归分工实现 all/any 字段规则与动态保存搜索。规则与当前集合/标签/快速搜索相交，保存项不冻结结果；更新名称和条件须明确保存。全文索引、回收站、书目合并及真实发行门槛仍为后续目标。实际验证证据记录在整改追踪中。


## D2c 当前 PDF 全文检索

基于当前 IR 的 FTS5 本地索引、短词/中文检索、PDF/页码/块身份、覆盖状态及显式清除/重建接入原生对话框；后台搜索和解析沿用窗口生命周期。扫描页无文本时明确提示，不把索引称 OCR。书目合并、回收站和既定发行门槛继续推进，实际检查结果见整改记录。


## 代码可维护性门槛

后续遵循 [开发约定](../AGENTS.md) 与 [可维护性说明](15-code-maintainability.md)：按类职责组织业务，跨功能校验/操作复用，关键注释中英文双语，优先清晰多行代码。既有服务、存储、页面和worker逐模块整改，重构不能改变隐私边界、事务或关闭语义；全仓复核尚未完成。
