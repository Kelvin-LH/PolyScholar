# 多智能体研发计划与交付门槛

日期：2026-10-02。目标为个人本地跨平台桌面研读工具；范围不扩展为 B/S、浏览器产品、团队服务或账户同步。界面依据 [UI 规范](10-ui-spec.md)。原有 P0 需求仍是目标范围，不代表已经交付。

文献管理新增 Zotero 对标要求，采用 [对标矩阵](12-zotero-parity.md) 的 Z-LIB-01–08 逐项验收，不能把基础列表、标签字符串和 PDF 导入称为完整对齐。

技术决策更新：全部自有应用代码用 Python；PySide6 原生桌面与 sqlite3/Python 服务，旧栈验证不作为新架构完成证据。三平台冻结包与安装仍须分别验收。

阶段状态（2026-10-03）：最新源码 `82cc4bf` 的三平台 core/native-gui 六项 [CI 37075308113](https://github.com/Kelvin-LH/PolyScholar/actions/runs/37075308113) 已通过。较早源码 `d83c4c0` 的专用冻结 CI 在 Windows AMD64/Linux x86_64/macOS arm64 全部成功，实际包导入、子进程、双引擎版本/依赖与中文路径迁移证据已核对；详细证据见 [整改追踪](14-review-remediation.md)。完整目标继续按 D1–D5 与 Zotero 对标矩阵验收，功能交付、冻结组件和实际安装分别记录，真实引擎/API、安装与安全等未验证门槛保持开放。

当前优先修复发布阻碍，暂不追加新格式或扩大 Zotero 功能范围。本轮将 Windows sidecar/引擎进程树统一纳入 Job 与启动门闩，完成情况和失败证据记入整改追踪；硬退出残留配置的恢复、Windows ACL 和真实安装仍是待验收项。该排序不缩减原有完整目标，也不把开发版记为正式发行完成。

两轮 macOS 原生迁移超时经固定阶段诊断和本机对照，确认检查脚本的轮询等待会拖慢 Python 后台线程。已改为真实 Qt 事件循环，补齐超时、异常及提前退出回归；生产持久化和30秒预算保留。`82cc4bf` 三平台完整迁移检查通过，合成预览 macOS0.387秒、Windows0.698秒、Linux0.555秒。Windows 223项核心回归成功（7项其他平台检查跳过），8项进程树专项实际通过；原始失败和修复证据保留在整改追踪。下一步优先凭据硬退出残留的安全恢复，真实引擎/API、Windows ACL 和安装验收不由源码 CI 代替。

本轮先重现两适配器硬退出后含密钥配置残留，再移除配置文件生成，改为 stdin 与固定版本内存配置入口；保留原上游 CLI 翻译流程。完整231项本机回归、后补8项专项、原生桌面及两个实际固定版本离线解析器/客户端构造检查通过，新三平台 CI 待核对。旧凭据残留、真实上游强杀、冻结新入口、Windows ACL、OS 凭据库和安装门槛继续开放，具体证据见整改追踪。

## 分阶段目标

1. **D1 可审查 UI 与桌面骨架**：六屏设计、真实空库、路由/导航、已有文献选择、明确能力状态，初始化桌面入口与构建流程。设计示例不写入用户库。
2. **D2 本地文献闭环**：PDF 文件选择、校验、哈希去重、复制与持久化，读写冲突/磁盘错误、重启保持，原件不变。库内检索仅本地执行。分 D2a 集合/子集合与多集合成员、标签/筛选；D2b 类型化元数据、父条目/多附件、重复候选与人工合并；D2c 高级/全文搜索、回收站、规范引文导入导出，不一次虚称 Zotero 全量一致。
3. **D3 阅读与翻译闭环**：真实 PDF 渲染/选段定位、固定版本引擎探测、OS 凭据库、授权、任务启动/取消、输出验证和本地任务记录。尚未接入能力不得启用。先合成/公开合法测试，不用用户私人论文或付费 API。
4. **D4 证据与引用闭环**：结构化摘要来源校验、实际引用处理器/合法样式、错误/降级、真实文件导出；用金标检查，不由 LLM 猜补。
5. **D5 跨平台发行**：Windows/macOS/Linux 分别构建、安装与完整路径验证，实际引擎资源联网载荷检查、秘钥和临时文件、SBOM 与许可。只发布经过验证的平台包。

D1/D2 是本轮开发方向，D3–D5 需持续推进，不能因 UI 原型完成就宣称 MVP 已完成。详细任务沿用 [实施路线](06-roadmap.md) 的 A01–A08 与 [产品需求](02-requirements.md) 中的需求 ID。

本轮新增可独立交付的桌面易用性工作：E01 自动发现/探测所选引擎解释器，自定义路径放折叠高级区；E02 可选择任务缓存目录，验证可写并明确上游资源缓存覆盖范围；E03 已生成译文 PDF 的原生保存导出，实际写入才成功，拒绝覆盖原件。它们不取代 Zotero 对标工作，也不能因设计写入文档就标为已实现。

## QA 检查清单

- LIB-01：真实空态、首次导入、损坏/伪 PDF、空文件、重复附件、特殊字符路径、重启保存；原件哈希保持不变。
- PRIV-01：模型 API 与资源下载按用户本轮授权默认允许，任务页不要求两个手动勾选；仍核对实际处理范围及目的地，图片外发等未授权扩展另行确认，密钥不进 argv/日志/普通持久化；Linux 无安全凭据库的明确失败路径。
- TRANS-02：进程错误、超时、取消、重复启动与输出路径冲突，部分结果不能标为完整成功；暂不支持的恢复/预算功能保持禁用。
- READ-01/SUM-01：真实页码/块锚点、解析修订变化、失效定位、缺证据状态，无假页面和假摘要。
- CITE-01：缺失元数据与格式差异、保存取消/错误、合法样式版本，成功必须对应实际文件。
- TRACE-01：本地记录与导出来源可核查，用户内容不自动标 AGPL，代码来源记录不作为法律授权证明，不做隐藏遥测。
- 界面：六屏键盘访问、长标题/路径、缩放、窄窗口、焦点和可访问名称；按钮能力状态与后端一致。
- Z-LIB：集合层级/循环拒绝、多集合成员不复制、移除与删除语义、标签联合搜索、不同条目类型字段、附件角色、重复候选人工决策和回收恢复，逐项核对对标矩阵。
- E01–E03：解释器缺失/错版本、自定义覆盖与发现优先级；缓存目录无权限/活动任务/旧缓存；导出取消、覆盖原件、磁盘写入失败、文件哈希保持。
- 发布：实际三平台 Qt 插件/密钥库/进程树与临时文件权限；无法执行的项目记录为未验证，不以 CI 图标代替。

## 定时推进与推送纪律

协调者通过 Codex 的当前聊天 heartbeat 配置周期研发；周期与自动化实际创建结果以聊天记录为准，本文不伪造已排定或已执行的定时任务。每轮先查看工作树、最新进度与检查结果，选择尚未完成的可验证任务，必要时重新组建多智能体团队。

只有形成实质变更且相关检查通过才提交并推送；没有变更不制造空提交。检查失败先修复，环境限制须记录。按用户选定的每小时周期报告实际进度；无变化时明确说明没有新增进展。不将私人文件、运行数据库、缓存、密钥或未授权数据推送 GitHub；不自动合并他人 PR 或发布未验证安装包。

定时研发是后续增量推进，不保证机器离线时执行，也不保证每个时间点产生可推送成果。每次交付列出改动、验证证据、限制和下一目标。
