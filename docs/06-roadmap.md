# 实施路线、资源与风险

技术决策更新：应用自有代码全部 Python，PySide6 Widgets 原生桌面、sqlite3 与 Python 工作进程。发行使用 PyInstaller 或 pyside6-deploy 自带 Python，不再使用 Rust/Go/Tauri/React/WebView，也不启动 HTTP 应用服务。详见 [架构](03-architecture.md)。

## 建议阶段

以下是 2–3 人小团队的初步范围估计，未做工程排期承诺。版面导出与三平台打包是主要不确定性。

| 阶段 | 估计 | 交付 / 完成门槛 |
|---|---|---|
| M0 需求验证与技术样例 | 1–2 周 | 用户访谈、60 篇合法语料、PDF/OCR/CSL 许可清单、按学科评测样例、决定独立工具或 Zotero 伴随模式 |
| M1 阅读闭环 | 3–4 周 | Python/PySide6 本地库、PDF 原文、选段 DeepSeek 与本地适配、预算/授权、术语和同步定位；三平台安装冒烟 |
| M2 研究闭环 | 3–4 周 | 全文续传、扫描 OCR、图文侧栏、证据摘要、引用导入导出；按 PRD 测试集验收 |
| M3 发布硬化 | 2–3 周 | 复杂版式降级、可选双语导出、数据恢复、权限和性能测试、签名包/SBOM；只发布通过验收的平台 |
| M4 生态扩展 | 单独估算 | 个人 Zotero 桥接、离线模型和大文献库优化；不包含 B/S 或团队服务 |

团队建议：一位 Python/Qt 桌面工程师、一位 Python/PDF 工程师，以及可兼职的科研质量/OCR 支持。兼职或单人开发会明显延长时间。产品无需自建服务器，所有阶段均为个人桌面应用，模型费由用户自行承担；没有实测 token 用量，不提供虚构的每篇论文费用。

## 可直接开发的任务

- A01 文献库和迁移：以初始 SQL 建对象文件库、去重与元数据冲突界面。
- A02 DocumentIR：做两栏/跨页/旋转/扫描混合样本、坐标变换和解析修订。
- A03 模型网关：DeepSeek/通用兼容接口/本地端点；外发确认、限流、费用和错误处理。
- A04 双语阅读：原译文同步、失败块、人工纠错与术语版本。
- A05 图文 OCR：候选框、低置信度提示、手工校正及只读原图。
- A06 证据摘要：结论与锚点、原文摘录核对、学科评审。
- A07 引用：选处理器、合法样式、金标条目和导出损失报告。
- A08 发行与许可：法律审核、贡献权利确认、SBOM/签名、三平台打包与隐私检查。

## 风险与停止门槛

| 风险 | 处理 / 停止门槛 |
|---|---|
| 和现成插件重复 | M0 无明显任务收益则转插件/伴随工具，减少独立库范围 |
| 许可冲突 | 集成代码采用 AGPL，仍须逐项审查模型/字体/传递依赖；进程隔离不免除许可义务 |
| 论文外发/保密 | 默认本地，按范围授权；无法明确提供商处理边界的文献不外发 |
| 图表或数值被改 | 原图不修改；数字/单位/数据图错误阻断发行 |
| 幻觉与错引用 | 锚点验证 + 人工证据抽查，不声称自动学术判断 |
| 跨平台包体/性能 | OCR 模型按需下载、固定校验；先 CPU-only 基准，GPU 为可选 |
| 源码合规风险 | 分发包与网络服务满足相应源码/通知义务；商业再许可需全体相关权利人同意 |

## 发布治理

main 分支保存可审查变更；核心 CI 与基线检查通过才合并。未验证能力必须写在 README 状态表。issue 用需求 ID 与验收条件追踪，公开问题不上传私人论文和 API 密钥；安全报告走私密渠道。下次需求评审围绕 M0 样例收益、AGPL 合规交付与最低平台版本，坚持个人客户端范围。
