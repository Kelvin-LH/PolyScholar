# Zotero 个人本地文献管理对标

核查日期：2026-10-02。用户要求文献管理对标 Zotero。本产品借鉴其个人本地管理工作流，并以功能与数据语义验收，不宣称完整复刻或当前已达功能一致。没有账户、群组、云同步、浏览器采集平台、论文公开发布或自动全文下载。

本轮源码核查已有基础是本地 PDF 导入、SHA-256 去重、标题/作者等简化字段、标签/笔记编辑与真实文献列表；集合层级、多集合成员、未分类视图及标签联合筛选已实现；托管多 PDF 附件已接入；类型化作者、外部链接、智能检索及去重合并仍待交付。实现状态必须随代码/测试证据更新，不能把文档规范当完成报告。

## 数据与界面语义

集合应是条目组织关系，不能等同文件目录。数据需要 collection parent、item-collection membership、typed item、ordered creators、attachment parent/role、tags、saved-search rules、trash state；所有关系由 SQLite 事务维护。接口扩展采用版本化迁移，已有用户库需备份，不能默默覆盖简化 Document 数据。集合关系从 v2 引入；v6 新增父文献/子 PDF 关系，根条目的原始 PDF 隐式保留，已有 ID、任务与证据不重写。类型化条目、保存查询和回收站仍为后续要求。

文献库工作流采用集合树/标签 → 条目及附件 → 信息/笔记/标签/附件详情；首次无条目仍为空。尚未接入的视图禁用并标明，不放示例论文凑齐集合。读论文和生成译文保留条目/附件上下文；译文产物可导出，但加入文献附件应有真实关系记录。

## 本轮额外易用性要求

- 引擎解释器自动发现并核对锁定版本；普通路径不强制手填，高级自定义可覆盖且需重新探测；安装缺失说明与真实状态一致。
- 用户可选择本机任务缓存目录，保存前检查可写、避免原件目录被清理，活动任务下禁止迁移；说明是否仅影响新任务及是否覆盖上游资源缓存。
- 已生成译文 PDF 走原生保存对话框导出，后端校验产物范围/哈希/PDF 文件头；取消不成功，拒绝覆盖原件，不伪称无损质量。
- 文本 API 与模型/字体下载按用户明确授权默认允许，任务请求带相应 true 字段，不再要求手动双勾选；目的地与输入范围仍可查看。图片外发等新增范围不由默认文本授权覆盖。

## 对标测试与完成判定

建立合成文献元数据与合法 PDF 测试集：一个条目加入两个集合；三级子集合及循环移动；组合标签；中英文多人/机构作者；同 DOI 不同版本；不同 DOI 同文件；父条目多附件；失效链接；全文索引失败；不同类型与缺字段引用；回收恢复。每个需求 ID 记录自动检查、桌面人工检查及平台状态。

只有逐项通过矩阵验收的能力才称“已对齐对应 Zotero 工作流”。全部条目管理、附件、集合、搜索、去重和引用闭环尚未完成时，总体状态为“部分对标，持续研发”。跨平台安装验收与上游真实翻译/联网载荷验证仍单独进行，不以文献管理单测通过替代。


## 托管 PDF 附件进展

原生详情支持添加、阅读及确认删除补充材料/已有译文。每个附件独立 PDF ID 贯穿阅读、翻译和证据摘要；同一条目仍只生成一条书目引用。主 PDF 暂不能单独移除或替换；其他附件删除仅移除受管副本及其任务/证据，外部来源保留。运行中的子附件任务阻止删除附件或整个条目。

重复导入同一附件返回原所属主条目；拒绝将同一 PDF 静默归入另一个条目，书目合并另行实现。导出防覆盖仍检查隐藏子附件的原始来源、硬链接及相同内容文件。此实现覆盖托管 PDF 的个人工作流，未覆盖官方附件功能全集。
