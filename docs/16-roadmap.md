# 开发路线图

记录:2026-10-04。这里是方向性规划,不是承诺清单;每项落地时按 [需求基线](02-requirements.md) 的诚实呈现原则单独验收,未实现的能力不进入界面。

当前已完成并验收的主线见 [审查整改追踪](14-review-remediation.md);agent 可编程入口的契约见 [cli.md](../cli.md) 与 [mcp.md](../mcp.md)。

## 1. UI 重构:更简洁

现状:文献详情右栏承载了书目字段、作者、摘要、三块 AI 评分、集合与附件,信息密度偏高;评分明细对话框内容完整但层级较深。

方向:

- **分层呈现**:书目编辑与 AI 结论分离——默认视图突出"分数 + 一句话理由",书目字段折叠为次级面板;
- **评分区轻量化**:论文分/置信度/提炼三块的默认高度进一步压缩,理由文本默认两行截断,展开按需;
- **导航简化**:五页结构重新评估,低频页(引用导出)考虑并入相关流程而非独立页;
- **一致的空态**:所有 AI 区块统一"暂无 + 如何产生"的引导文案,不出现无行动建议的空白。

验收原则:1440×960 至 960×720 与 200% 缩放下不出现横向滚动;长标题/长理由/空库状态纳入人工检查;重构不改变任何 CLI/MCP 契约。

## 2. 评分标准的联网核验:研究进度与 SOTA 感知

问题:当前两份量表规定盲评**不联网**(rubric 是唯一依据),这是为了可复现与隔离。但代价明确——agent 无法知道"这个问题今年是否已被更好地解决""报告的数字相对当今 SOTA 处于什么水平",创新点与实际效果两个维度因此只能评"论文自证的质量",评不了"领域内的相对位置"。

方向:在**不破坏盲评可复现性**的前提下增加独立的联网核验层:

- **独立通道**:联网核验作为单独的第三方报告(如 `sota-check`),与现有 paper/confidence 分数分开存储与展示,绝不回写、不污染盲评明细;
- **显式授权**:核验是用户触发的动作,明确展示将查询的来源(arXiv/学术检索)与发送内容(论文标题/主张清单,非全文);
- **快照留档**:检索到的对比工作以"查询时间 + 来源 + 摘录"冻结进报告,评分结论可追溯到当日的领域快照,不同时间的核验结论允许不同;
- **量化输出**:核验报告给出"主张 X 与已检索到的工作重叠/超出"的对照条目,以及当前领域 SOTA 参照值表,供人阅读,不自动折算成分数。

验收原则:核验报告的每条对照可点击溯源;断网时明确"无法核验"而不是降级为本地猜测;授权与实际外发内容一致。

## 3. 置信度的开源真实性核验

问题:大量论文声称"代码将开源"或给出 GitHub 链接,但实际未开源、只开源一部分、或仓库与论文描述不符;即便真实开源,代码质量也参差。当前置信度量表只能对"论文文本内的制品定位"计分(T3),无法核验链接背后的现实。

方向:为置信度维度增加**制品真实性外核**(同样独立于盲评、用户触发、快照留档):

- **仓库存在性与一致性**:链接是否可访问、仓库是否为空壳/占位、提交历史是否早于或伴随论文、README 与论文描述的功能是否对应;
- **开源完整性**:声称开源的模块是否都有对应代码;只有推理脚本没有训练/数据构建流程、只有骨架没有可运行入口等情况分档记录;
- **可复现信号**:依赖说明、随机种子/配置、数据获取说明、许可文件;缺失项逐条列出,不猜测;
- **代码质量信号**(谨慎):目录结构、测试存在性、CI 配置等**可客观观察**的指标;不做主观代码评审,不做安全扫描结论;
- **输出与展示**:核验结果作为置信度的补充报告("开源核验:声称 3 项,可验证 1 项,空壳 1 项,不符 1 项"),在评分明细中独立成节,不直接改写置信度分数。

验收原则:所有核验基于核验时刻的仓库快照(GitHub API/克隆),留 SHA 与时间;私有仓库/删除的仓库如实标注"不可核验";核验过程不向第三方发送论文正文。

## 4. 其他已识别方向(次优先)

- **下载异步化**:`add --arxiv` 长下载改为任务化(job id + `jobs` 轮询),避免 MCP 客户端超时与锁占用困惑(2026-10-03 实战反馈);
- **聚合产物精简回显**:`score aggregate` 已是轻载荷,`score show` 默认精简的契约变更待评估;
- **评分历史**:同一文献多轮评分的版本保留与对比(当前为覆盖式);
- **安装包分发**:冻结打包的三平台验收长期开放(见 [14](14-review-remediation.md) 的验收门槛)。
