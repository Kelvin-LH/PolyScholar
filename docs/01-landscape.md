# 现状、问题与产品定位

初始调研：2026-10-01；许可与集成决策更新：2026-10-02。下列为官方文档和仓库能力核查，不是对中国高校学生的统计调查。用户提出的问题作为待验证的需求假设，不推断所有高校或所有软件都如此。

## 现状与差距

| 工具类别 / 代表 | 已有能力 | 本项目要验证的剩余问题 |
|---|---|---|
| 文献管理 / Zotero | PDF 阅读、批注、笔记和 CSL 引用；可通过插件扩展 | 多插件版本、权限、译文与证据锚点如何统一；应访谈后判断插件组合是否已够用 |
| PDF 翻译 / PDFMathTranslate、BabelDOC | 科研 PDF 翻译、双语输出和版面处理；前者也列出 Zotero 集成 | 复杂图内文字、扫描页、字体回退、图表保护，以及与统一文献数据/摘要证据的完整衔接 |
| 文档结构提取 / Docling | OCR、布局与表格处理 | 结构提取不是最终保留排版翻译；模型权重、运行时和字体还需独立许可核查 |
| 通用 LLM/API | 翻译、术语解释、结构化总结 | 长文切块、幻觉、费用、数据外发与可靠页码定位需要产品层处理 |

Zotero 已有大量引用样式，所以“没有适配参考文献格式”应理解为跨工具的样式和元数据衔接不足，而不是市场上没有解决方案。PDF 翻译已有保留排版方案，项目差异化要通过用户测试证明。

## 根因分析

1. PDF 记录的是页面绘制，不一定包含段落语义；双栏、跨页段落、断词导致错误阅读顺序。
2. 译文长短与原文不同，硬塞进原框会溢出；全页重排又会移动公式和图表。
3. 图中文字可能是矢量字形、栅格像素或公式；普通文本翻译看不到它们。
4. 元数据、页内批注、译文和总结各自保存在不同系统，缺少稳定文献 ID 与段落 ID。
5. 参考文献问题分为元数据错误、交换格式丢字段、输出样式不符；仅让 LLM“改格式”不能修复来源错误。

## 产品定位

一个“证据可追溯的双语研究工作台”。核心价值是导入一次，在同一文献上阅读、理解、记录和引用。原文可信，译文辅助，摘要可复核；对复杂图不承诺无损重绘。

初始用户：中文母语硕博学生和本科科研学生；仅面向个人使用；导师也以个人客户端使用，不设置课题组管理角色。首期中文界面，英语备选。避免强制注册、本地阅读依赖云端、强行替代整个 Zotero 生态。

## 需要先验证的假设

- 招募 15–20 位、至少覆盖理工/医学/社科三类学科；其中至少 5 位已有 Zotero 插件使用经验。
- 用同一批有阅读权的论文，比较“现用工具链”“Zotero + 翻译插件”“独立工作台”；每人执行找结论、理解一张图、生成参考文献三类任务。
- 收集任务时间、人工切换次数、错误定位、图中文字理解、API 成本、主观负担；不收集私人文献目录或未发表稿件。
- 若插件方案达到相同任务成功率且切换问题很小，优先做 Zotero 伴随工具而非独立文献管理器。
- 当前没有用户人数、付费意愿、市场规模或竞品性能对比数据；不得将这些假设用于商业宣传。
