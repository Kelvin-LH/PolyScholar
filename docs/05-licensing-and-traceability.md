# AGPL 许可、来源追踪与合规交付

决策更新：2026-10-02。用户明确选择“AGPL-3.0 集成，接受商用但落实相应源码公开义务”。此决策替代初始禁止未经授权商用的要求；仓库不保留额外非商用条款。

## 许可

项目原创代码采用 AGPL-3.0-only，LICENSE 为未修改的 GNU AGPL v3 全文。BabelDOC 0.6.4 与 PDFMathTranslate 1.9.11 保留上游原许可，副本见 licenses/upstream。上游具体版本的文件头、第三方例外和依赖许可仍按原文执行，不一概声称全部代码都是本项目原创。

AGPL 允许商业使用。防止代码被用于封闭修改版时，应依赖适用的相应源码义务；不能将“允许商用”改写为“商业需要购买许可证”。AGPL 也不是所有企业内部使用都必须向全世界发布全部源码。

## 个人桌面使用

产品不采用 B/S，不建立账户、授权服务器、云文献库或网络应用服务。个人自行使用和修改而不分发、不以修改版提供网络交互服务时，通常没有向公众发布修改源码的要求；下表网络服务项用于解释 AGPL 的适用边界，并非产品路线。

## 交付义务与实现计划

| 情况 | 要求 / 项目实施 |
|---|---|
| 原始源码分发 | 保留许可、版权和适用通知；提供可实际获取的源码 |
| 修改源码分发 | 清晰标识修改及日期；相应覆盖代码按 AGPL 提供，保留通知 |
| 二进制/容器发行 | 根据 AGPL 第 6 条选择合规源码交付方式；项目优先在同一下载页同时提供完整相应源码包与构建说明，不能仅提供失效上游链接 |
| 修改版通过网络交互 | 根据第 13 条，显著向远程交互用户提供该版本相应源码的免费获取入口 |
| 桌面合规入口 | 设计“关于 → 源码与许可”，展示客户端版本、commit、上游版本、许可证与源码获取方式；不实现 /about/source 服务端 |
| 构建与安装 | 相应源码范围包含适用的构建/安装脚本、修改和依赖要求；适用的 User Product 情况评估安装信息义务 |

相应源码范围须按实际链接、修改、组合、分发方式和许可证定义分析；独立进程是工程边界，不能自动判定许可无关联。本方案统一以 AGPL 发布原创集成层，减少额外限制的冲突，但不是完整发行包的法律认证。

## 来源与关键追踪

| 关键部位 | 追踪 | 当前状态 |
|---|---|---|
| 源码 | AGPL 文件头、版权、commit、文件哈希清单 | 已实现 |
| 引擎任务 | 引擎名、固定版本、输入哈希、语言与页范围 | CLI 成功后输出本地 manifest |
| 模型边界 | provider/model、授权范围、usage、预算决策 | Rust 定义 ModelRequested；严格网关待实现 |
| 文档与摘要 | 解析修订、block ID、页码、证据摘录 | Rust 校验参考；真实解析/总结待实现 |
| 引用/产物导出 | 应用版本、样式哈希、输出哈希 | 引擎输出哈希已实现；引用服务待实现 |
| 官方发行 | 签名清单、SBOM、相应源码包与桌面来源说明 | 计划，当前清单未签名 |

五类领域追踪点：DocumentParsed、ModelRequested、SummaryCreated、CitationExported、ArtifactExported。Rust 本地审计类型无正文、密钥、身份和设备字段。引擎输出 manifest 只留本地，但含模型、源文件哈希和输出文件名，仍可能关联文献，不宜自动公开；问题报告由用户预览并脱敏。

来源标记不属于商用锁，不检测用户真实商业目的。公开源码可以被修改和移除标记；AGPL 义务是否违反需要核查实际行为和证据，不能仅按标记缺失下结论。不得远程停用、删除私人文献或秘密上传遥测。

## 权利与隐私

- 保留本项目及上游版权；上游名称仅用于真实来源说明，不暗示背书。
- 不把 AGPL 源码义务扩大到 API 密钥、学生论文、私人数据库或个人数据。
- 用户输出内容不因使用软件自动成为 AGPL；涉及第三方论文/译文权利时按内容授权另行处理。
- 商标/Logo 保护官方身份，不能作为禁止合法商用、要求付费或删去必要来源通知的借口。
- 没有后台遥测；诊断上传必须用户主动选择、预览、脱敏并说明保留期限。本地事件可查看删除，建议 30 天滚动保留。
- 公开违规销售/源码缺失的核查可作为后续人工工作；本任务未创建持续监测服务或向他人发送通知。
