# 提示词:生成《论文置信度评分量化打分文档》

> 使用方法:把本文件全文粘贴给 GPT(或其他 LLM),它将产出一份《论文置信度评分量化打分文档》。
> 生成后请将产物保存为 `rubrics/confidence-scoring.md`,供后续 agent 评分时作为唯一依据读取。
> 若生成结果缺少本提示词要求的任一章节,把缺失章节的名称原样发回给它要求补齐。

---

你是一名科研诚信与证据评估专家。请为我生成一份《论文置信度评分量化打分文档》,用于让**不同的 AI agent、不同的 LLM** 对同一篇论文的**真实性与可信度**独立打分(0–100,分数越高越可信),目标是不同模型对同一篇论文得出尽可能一致的结论。这份文档是评分的唯一依据,评分 agent 不允许引入文档之外的隐性标准。

## 评估对象与边界

- 以 arXiv 预印本为主(通常未经同行评审),评估的是"**这篇论文所言可信的概率**",不是学术质量高低;
- 明确区分:低置信度 ≠ 论文无价值,只代表"应当更谨慎地引用其结论";
- 评分 agent 只依据论文文本本身与可核验的内部一致性,**不做联网检索**(外部核验是后续独立流程)。

## 文档必须覆盖的重点维度(总满分 100,权重自行设计但需说明理由)

1. **证据强度**(数据集与实验设置描述是否完整到可复现;统计口径、指标定义是否清晰)
2. **内部一致性**(数字、图表、正文三处是否互相吻合;前后陈述是否矛盾)
3. **来源可溯源性**(作者与机构是否真实可查、引用是否真实对应、是否有代码/数据链接)
4. **结果合理性**(性能声明是否超出领域常识边界;提升幅度是否异常)

## 文档必须包含的章节(缺一不可)

### 1. 维度与权重表
每个维度:名称、权重、考察要点、明确的"无法判断时"处理(按哪个档位计分,不得悬空)。

### 2. 高考式分档锚点
总分与每个维度各设 5 档(如:高度可信 / 较可信 / 存疑 / 明显存疑 / 高度存疑),每档给出:
- 分数区间;
- **可观察的客观特征**(例:"正文与图表数字全部一致且公开了代码与数据链接"属于哪一档);
- 相邻档判定规则。

### 3. 红旗清单(造假与不可信迹象的扣分细则)
列出可从文本层面识别的红旗及对应扣分,例如:数据在正文与图表中不一致、结果提升幅度异常且无解释、图片/表格描述与图内容不符、引用列表存在明显不相关的凑数引用、作者信息不可核验、"前所未有""完美解决"类绝对化声明无证据支撑、实验设置缺少关键细节(随机种子、划分方式、评测脚本)。每条红旗须写明:识别方法、扣分幅度、以及"可能是无意失误"与"疑似造假"的区分判据。

### 4. 三子代理盲评流程(参照高考阅卷)
- 三个子代理互相不可见,独立输出完整评分;
- 每个维度判断必须引用原文证据(章节号或原句摘录);
- 汇总:取三份总分中位数为最终置信度;极差 > 15 分触发复核并输出分歧点对照表;
- 同时保留三份子评分,禁止只报最终分。

### 5. 跨模型一致性纪律
- 只依据锚点与原文证据,禁止凭"名气""直觉"加减分;
- "无法核验"统一按文档规定的档位处理,不同 agent 不得自行发挥;
- 输出前逐项自检锚点对照表。

### 6. 机器可读输出格式(JSON Schema)
定义置信度报告的 JSON 结构,程序将直接导入。必须包含:
```
total(0-100 数值)、dimensions:[{key,name,max,score,rationale}],
red_flags:[{flag, evidence, severity}],
verdict(高度可信/较可信/存疑/明显存疑/高度存疑),
sub_scores:[三个子代理各自的 total],
aggregation:{method:"median", spread, rechecked:boolean}
```

## 生成要求
- 文档为中文,面向执行评分的 AI agent,指令式行文;
- 所有档位必须可操作、可对照;红旗必须可从论文文本识别,不得依赖外部知识库;
- 篇幅以"评分 agent 一次读入即可执行"为限。
